## content-list.js v1.2 特性

### 1️⃣ 服务端去重

```
页面加载 → collect card URLs → POST /prompt/check-exists
  → 返回已存在的 URLs → 标记为"已采集"（显示绿色按钮/跳过）
  → SPA 渲染前最多重试 3 次（每次 1.5s）
```

- **双通道去重**：`collectedUrls`（source_url 精确匹配，高优先级）+
  `collectedTitles`（标题降级匹配，兼容无 URL 场景）
- **跨会话持久化**：即使浏览器重启（localStorage 清空），API 检查仍能识别已入库内容
- 去重结果会刷新卡片按钮状态（`scanCards()` 重新注入）

### 2️⃣ 批量采集模式

**入口**：页面右上角浮动「📦 批量」按钮

**激活后**：
- 按钮变红「📦 退出批量」
- 未采集的卡片右上角出现紫色复选框
- 底部弹出操作栏：已选数量 + 批量采集 + 取消

**流程**：
```
勾选卡片 → 点击「批量采集」
  → 逐张提取（优先 fetch，回退弹窗）
  → 追加到批量列表 + 标记去重
  → 自动提交（autoSubmit 开启时）
  → 关闭弹窗 → 下一张
  → 完成后显示结果：✅ 全部成功 或 ⚠️ 成功 N 失败 M
  → 自动打开侧边栏
```

- 已采集卡片自动跳过，不计入失败
- 单张超过 2 次提取失败标记为失败，继续下一张
- 中途可通过「取消」退出批量模式

## 验证

1. **去重**：在 opennana 采一个提示词 → 提交 → 刷新页面 → 该卡片应显示「✓ 已采集」
2. **批量**：点「📦 批量」→ 勾选多张卡片 → 点「批量采集」→ 观察进度逐个推进
3. **跨浏览器重启**：关闭浏览器再打开 → 卡片从 API 查询已采集状态 → 正确标记
