# Skill as a Service（SaaS）产品需求文档

## 1. 项目信息

| 字段 | 内容 |
|------|------|
| 产品名称 | skill_as_a_service |
| 语言 | 中文 |
| 技术栈 | Vite + React + MUI + Tailwind CSS（Skill Store + 创作者/用户后台）；Go / Node.js 服务层（未指定时按团队现有栈） |
| 原始需求 | WorkBuddy 拟将 Skill（技能）能力封装为服务，让外部系统/开发者也能调用 WorkBuddy 的 Skill 能力。 |
| 已确认方向 | **B2C 优先**：面向普通消费者，打造 C 端 Skill 市场，用户直接在网页/客户端使用 Skill，无需 API 调用。 |

---

## 2. 产品定义

### 2.1 Product Goals

1. **C 端 Skill 市场**：打造普通消费者可发现、订阅、直接使用的 Skill Store，降低 AI 能力使用门槛。
2. **创作者生态**：吸引个人创作者与内容团队上架 Skill，通过平台会员、按次付费、Skill 订阅与创作者分成实现变现。
3. **平台商业化**：以平台会员 +  Skill 订阅 + 按次付费 + 创作者分润的组合模型，构建可持续的 C 端 Skill 经济。 |

### 2.2 目标用户与使用场景（B2C 优先）

| 优先级 | 用户角色 | 使用场景 | 核心诉求 |
|--------|----------|----------|----------|
| P0 | **普通消费者（C 端用户）** | 在 Skill Store 浏览、订阅、直接使用 Skill 完成写作、学习、娱乐、办公等任务 | 门槛低、即开即用、价格透明、体验流畅 |
| P0 | **Skill 创作者 / 个人创作者** | 把自研 Skill 上架到 Skill Store，设置价格/会员权益，获取持续收益 | 上架简单、定价灵活、收益透明、快速提现 |
| P1 | **内容团队 / MCN / 小工作室** | 基于 WorkBuddy 创作系列 Skill 并建立品牌专区 | 可展示品牌、粉丝沉淀、数据分析 |
| P1 | **WorkBuddy 平台运营** | 审核 Skill、管理创作者、运营推荐位、结算分润 | 可控、可度量、可结算、可治理 |
| P1 | **外部系统集成开发者（保留）** | 未来可能通过 API 调用平台能力（非 P0） | 标准 API、文档清晰 |
| P2 | **企业客户 / 企业开发者** | 未来可能面向企业提供团队版或私有化 | 稳定、可审计、可管控 |

### 2.3 用户故事

1. **作为** 普通消费者，**我希望** 在 Skill Store 首页通过分类/推荐找到解决具体问题的 Skill，**从而** 无需配置即可直接使用。
2. **作为** 普通消费者，**我希望** 对喜欢的 Skill 进行订阅或按次付费，**从而** 按需获得高级能力而不被强制购买平台会员。
3. **作为** 普通消费者，**我希望** 使用过的 Skill 可以收藏、评分、评论，**从而** 快速复用并帮助其他用户决策。
4. **作为** Skill 创作者，**我希望** 在创作者后台上传/配置 Skill、设置封面与价格，并查看收益，**从而** 获得创作回报。
5. **作为** 平台会员，**我希望** 免费或折扣使用会员专属 Skill，**从而** 提升会员价值感知。
6. **作为** 平台运营，**我希望** 通过推荐位、榜单、活动运营优质 Skill，并自动结算创作者分成，**从而** 激励高质量生态。

## 3. 市场调研与竞品分析

### 3.1 竞品概览（C 端 Skill / Bot 市场）

| 竞品 | 定位 | 能力形态 | 商业模式 | 用户体验 | 优点 | 缺点 |
|------|------|----------|----------|----------|------|------|
| **OpenAI GPTs / GPT Store** | 面向 C 端和企业的 GPT 应用商店 | 可视化配置 GPT + Actions + 知识库 | 终端用户订阅 GPT Plus/Team/Enterprise；创作者分成计划长期未落地 | ChatGPT 内嵌使用，聊天式交互 | 流量入口大、品牌强、用户门槛低 | 创作者变现弱、生态封闭、无法脱离 ChatGPT 使用、外部系统调用受限 |
| **Coze 扣子商店** | 字节跳动 C 端 Bot 市场 | 可视化 Bot、插件、工作流、知识库 | 基础免费；商业化按 API/企业版 | 飞书/微信/网页多渠道，聊天式交互 | 中国生态强、IM 集成好、创作者工具完善 | 强绑定字节生态，开放性一般，C 端付费心智弱 |
| **Poe** | Quora 旗下 AI Bot 平台与市场 | 聚合多模型 + 创作者 Bot | 平台订阅（Poe Prime）+ 按条消息付费（creator price per message）+ 创作者分成 | 网页/移动端，聊天式交互，Bot 列表清晰 | 模型聚合强、创作者可自主定价、按次付费模式清晰 | 国内访问受限、C 端付费转化依赖订阅习惯 |
| **FlowGPT** | 全球开源 AI Prompt / Bot 社区 | Prompt 分享、Bot 创建、社区交流 | Freemium + 创作者打赏/订阅（部分功能） | 社区化、UGC 氛围强，Prompt 模板丰富 | 社区活跃、创作者激励早、模板丰富 | 产品力偏工具社区，C 端付费与体验闭环较弱 |
| **Character.ai** | 角色扮演/情感陪伴 AI 平台 | 用户创建虚拟角色并对话 | 平台订阅（Character.ai+）+ 无明确创作者分成 | 强沉浸式聊天，角色人格化 | 用户粘性极高、UGC 角色丰富、情感陪伴心智强 | 主要面向娱乐场景，生产力 Skill 渗透率低，创作者变现弱 |
| **Claude Projects** | Anthropic 推出的项目级 AI 工作空间 | 为项目组织文档、对话、知识库 | 按 Claude Pro/Team 订阅计费 | 工作空间式，偏生产力 | 长文本、文档组织能力优秀 | 无公开市场，创作者无法分发，生态封闭 |
| **Dify Marketplace** | 开源 LLM 应用平台插件市场 | 插件、工作流、Agent | 开源免费；企业版/云服务付费 | 开发者导向，配置化 | 开源灵活、生态成型 | 面向开发者而非普通消费者，C 端体验弱 |
| **Microsoft Copilot Studio** | 企业级 Agent 构建平台 | 低代码构建 Copilot | 按消息/会话/容量计费 | Microsoft 生态深度集成 | 企业集成度高、合规强 | 强绑定 Microsoft 生态、成本高、非 C 端市场 |

### 3.2 C 端竞品体验差异总结

| 维度 | GPTs Store | Coze 商店 | Poe | FlowGPT | Character.ai | Claude Projects | WorkBuddy 机会点 |
|------|------------|-----------|-----|---------|--------------|-----------------|-------------------|
| 使用门槛 | 低（ChatGPT 用户） | 中（需配置 Bot） | 低 | 中（Prompt 为主） | 低 | 中 | 进一步降低：打开即用，无需聊天配置 |
| 付费模式 | 平台订阅 | 免费为主 | 平台订阅 + 按次付费 | Freemium | 平台订阅 | 平台订阅 | 平台会员 + 按次 + Skill 订阅 + 创作者分成 |
| 创作者变现 | 弱 | 弱 | 强（按条定价） | 中 | 弱 | 无 | 强：创作者可自主定价、订阅、分成 |
| 生态开放 | 封闭 | 半开放 | 中 | 开放 | 封闭 | 封闭 | 开放 Skill 市场，支持创作者品牌沉淀 |
| 场景覆盖 | 通用/办公 | 办公/IM | 通用 | 通用/创意 | 娱乐/陪伴 | 生产力/项目 | 聚焦“原子 Skill”，覆盖办公、学习、生活 |
| 中国市场 | 弱 | 强 | 弱 | 中 | 弱 | 弱 | 中国本土化、支付/会员体系成熟 |

### 3.3 差异化定位（B2C Skill 市场）

| 维度 | 市场主流 | WorkBuddy Skill as a Service 定位 |
|------|----------|------------------------------------|
| 形态 | 多为 Chatbot / Agent 平台 | 以 **Skill（原子能力）** 为核心，强调“打开即用” |
| 目标用户 | 开发者、企业 IT、C 端聊天用户 | **C 端普通消费者优先**：浏览 → 订阅/购买 → 直接使用 → 评价 |
| 使用方式 | 聊天对话或 API | 网页/客户端直接调用，无需 API 或编程 |
| 商业模式 | 平台订阅、按 token、打赏 | **平台会员 + 按次付费 + Skill 单独订阅 + 创作者分成** |
| 分发机制 | 应用商店式推荐 | **Skill Store**：分类、搜索、推荐、评分、收藏、会员专区 |
| 变现 | 平台侧收益为主 | 平台 + 创作者双赢：创作者可自主定价、订阅、分成、提现 |

## 4. 技术规范与需求池

### 4.1 核心功能架构（B2C）

```
┌────────────────────────────────────────────────────────────┐
│                    C 端用户（Web / App / 小程序）              │
│  浏览 Skill Store → 订阅/购买 → 直接使用 Skill → 评分/收藏     │
└────────────────────┬───────────────────────────────────────┘
                     │  HTTP / WebSocket / 表单交互
┌────────────────────▼───────────────────────────────────────┐
│                  Skill 接入与执行层                          │
│  用户鉴权 → 订阅/权限校验 → 调用 Skill 执行引擎 → 返回结果      │
│  ├─ 平台会员权益校验                                        │
│  ├─ 按次付费扣费                                            │
│  └─ Skill 单独订阅校验                                      │
└────────────────────────────────────────────────────────────┘
                     │
        ┌────────────┼────────────┐
        ▼            ▼            ▼
   Skill Store   创作者后台    平台运营后台
   （发现/使用）  （创作/收益）  （治理/结算）
   用户个人中心
```

### 4.2 需求池

#### P0（Must Have）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| P0-1 | **Skill Store 前台** | 支持分类、搜索、推荐、Skill 详情、免费/付费/会员标识、订阅/购买/立即使用按钮。 |
| P0-2 | **C 端用户直接运行 Skill** | 用户在 Skill 详情页或我的 Skill 中点击即可使用，无需 API 调用或编程。 |
| P0-3 | **用户账户与订阅管理** | 支持注册/登录、平台会员订阅、Skill 单独订阅、按次付费、我的订阅列表、续费/取消。 |
| P0-4 | **统一鉴权与权限控制** | 支持平台会员权益校验、Skill 订阅状态校验、按次付费扣费。 |
| P0-5 | **创作者后台** | 支持 Skill 创建、版本管理、发布、封面/介绍、定价设置（免费/按次/订阅/会员免费）。 |
| P0-6 | **创作者分润结算** | 按 Skill 使用收益向创作者分成，支持收益明细、结算周期、提现申请。 |
| P0-7 | **平台运营后台** | 支持 Skill 上下架审核、创作者资质审核、价格策略配置、分润比例配置、推荐位运营。 |
| P0-8 | **评分/评论/收藏** | 消费者可对 Skill 打分、写评论、收藏；创作者可回复评论。 |
| P0-9 | **调用监控与告警** | 提供调用次数、成功率、延迟、错误码等核心指标 dashboard 与告警。 |

#### P1（Should Have）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| P1-1 | **Skill 版本升级与兼容性** | 创作者发布新版本，消费者可选择是否升级；旧版本支持 deprecate 策略。 |
| P1-2 | **Skill 推荐与运营位** | 基于使用量、评分、收入等数据生成热门/精选/新品/会员专属榜单。 |
| P1-3 | **用户个人中心增强** | 历史使用记录、收藏夹、消息通知、会员权益中心、发票与账单。 |
| P1-4 | **多语言 SDK / 开放 API** | 面向未来外部开发者提供标准 API 与 SDK（非 P0）。 |
| P1-5 | **沙箱环境** | 创作者可在不扣费环境下测试 Skill，支持模拟返回和日志回放。 |
| P1-6 | **Webhook / 事件订阅** | 订阅到期、扣费成功、Skill 更新等事件可推送到创作者或外部系统。 |
| P1-7 | **内容团队 / 品牌专区** | 支持机构/团队账号、品牌专区、批量管理 Skill。 |

#### P2（Nice to Have）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| P2-1 | **外部 API 调用** | 允许外部系统/开发者通过 API 调用 Skill。 |
| P2-2 | **Serverless 执行器** | 支持用户上传自定义执行镜像或函数，平台托管运行。 |
| P2-3 | **Skill 组合编排** | 允许将多个 Skill 组合成 Workflow / Agent 再对外暴露。 |
| P2-4 | **AI 辅助生成 Skill** | 通过自然语言描述自动生成 Skill 定义和参数 schema。 |
| P2-5 | **开放插件协议（MCP/Function Calling）** | 兼容外部工具生态，降低 Skill 迁移成本。 |
| P2-6 | **多租户与私有化部署** | 企业团队版、私有化交付（非 C 端 P0）。 |

### 4.3 Skill 调用与计费模型设计（B2C）

| 维度 | 说明 |
|------|------|
| Skill 使用入口 | Skill Store 详情页、我的订阅、历史记录、收藏夹 |
| Skill 定价模式 | 创作者可选择：**免费**、**按次付费**、**Skill 单独订阅（月/年）**、**平台会员免费**、**免费试用 + 付费升级** |
| 平台会员 | 月卡/年卡会员：免费使用会员免费 Skill、折扣购买付费 Skill、优先客服 |
| 计费单元 | 按次调用、按输入输出 token、按执行时长 |
| 平台收入 | 平台会员费 + 按次付费抽成 + Skill 订阅抽成（建议 P0 平台抽成 20%） |
| 创作者结算 | 日汇总 + 月结算；支持查看实时收益、月度账单、提现到绑定账户 |
| 欠费策略 | 余额不足或会员到期时先预警，再限制高级 Skill 调用，最后暂停 |

### 4.4 安全与合规

- 强制 HTTPS/TLS；用户账户支持 MFA、登录保护。
- Skill 发布需通过平台审核，涉及敏感内容需额外安全评估。
- 用户输入与 Skill 输出需接入内容审核（moderation）。
- 调用日志保留不少于 180 天，支持审计追溯。
- 创作者需实名认证后方可提现。

## 5. UI 设计草稿

### 5.1 Skill Store 前台（P0 核心）

1. **首页**：
   - 顶部搜索框 + 热门分类标签（办公、学习、编程、生活、娱乐、设计）。
   - 精选推荐位（轮播/卡片）。
   - 热门 Skill、新品上架、付费 Top 榜、会员免费专区。
2. **分类列表页**：按场景分类，支持筛选（免费/付费/会员/高评分）。
3. **Skill 详情页**：
   - 名称、图标、创作者、评分/评论数、使用次数。
   - 功能介绍、效果示例、使用入口（表单/聊天/一键执行）。
   - 价格展示（免费/按次/订阅/会员免费）+ 订阅/购买/立即使用按钮。
   - 评论区、收藏按钮、分享按钮。
4. **我的 Skill / 订阅**：已订阅 Skill 列表、使用历史、续费/取消订阅。
5. **使用界面**：Skill 运行时页面（输入表单/聊天窗口/结果展示）。

### 5.2 用户个人中心（P0）

1. **账户信息**：头像、昵称、会员状态、余额。
2. **我的订阅**：平台会员、Skill 单独订阅、到期时间。
3. **我的收藏**：收藏的 Skill 列表。
4. **历史记录**：使用过的 Skill 历史与结果。
5. **账单与发票**：消费明细、充值、发票申请。
6. **消息通知**：订阅到期、Skill 更新、收益到账（创作者）。

### 5.3 创作者后台（P0 核心）

1. **Skill 列表页**：我创建/上架的 Skill，含状态、版本、使用次数、订阅数、收入。
2. **Skill 编辑器**：基本信息、图标、介绍、参数 schema、执行逻辑、定价设置、版本管理。
3. **收益看板**：总收入、分成后收入、按 Skill 收入、结算记录、提现申请。
4. **数据看板**：使用次数、评分、转化率、用户画像。
5. **评论管理**：回复评论、举报恶意评论。

### 5.4 平台运营后台

1. **Skill 审核**：待审核列表、详情、通过/驳回/下架/置顶推荐。
2. **创作者管理**：资质审核、违规处理、分润账户管理。
3. **平台大盘**：总使用次数、活跃 Skill、GMV、会员数、TOP 10 Skill、创作者分成总额。
4. **计费策略**：会员套餐、Skill 定价模板、平台抽成比例、提现规则。
5. **推荐运营**：配置首页推荐位、榜单算法权重、会员专区、活动 banner。

## 7. 待确认问题

1. **Skill 运行时形态**：C 端用户是直接聊天式使用 Skill，还是表单/向导式输入？是否支持多轮对话？
2. **技术栈**：Skill 执行引擎是否复用现有 WorkBuddy 运行时，还是独立部署一套服务？
3. **平台会员权益**：会员是“全场部分 Skill 免费”还是“全场折扣”？会员免费 Skill 如何与创作者结算？
4. **定价自主权**：创作者是否可完全自主定价（按次/订阅），还是平台提供定价模板？
5. **合规边界**：C 端内容审核、数据驻留、未成年人保护、支付牌照/税务合规如何处理？
6. **分成政策**：平台与 Skill 创作者的分成比例、结算周期和提现方式（建议 P0 固定 20%）。
7. **存量 Skill**：现有 WorkBuddy Skill 是否需要改造才能上架到 C 端 Skill Store？

> **已确认**：B2C 优先（普通消费者为 P0 目标用户）；产品形态为 C 端 Skill 市场，用户直接浏览 → 订阅/购买 → 直接使用 → 评分/评论/收藏；商业模式为平台会员 + 按次付费 + Skill 单独订阅 + 创作者分成；外部 API 调用、SDK、开发者后台降级为 P1/P2。

---

## 8. 关键结论

- **市场机会**：C 端 AI Skill 市场存在明显空白。GPT Store 创作者变现弱、Poe 国内弱、Character.ai 偏娱乐，WorkBuddy 可聚焦“生产力 Skill 的 C 端市场”。
- **核心打法**：以 **C 端 Skill Store** 为矛，先降低普通消费者使用 AI 的门槛，再吸引创作者上架优质 Skill，形成平台会员与创作者分润的闭环。
- **商业模型**：平台会员 + 按次付费 + Skill 单独订阅 + 创作者分润，平台抽成建议 P0 期固定 20%。
- **P0 必做**：Skill Store 前台、C 端直接使用、用户账户与订阅管理、创作者后台、创作者分润结算、平台运营后台、评分/评论/收藏。
- **P1/P2 保留**：外部 API、SDK、多租户、私有化，为后续 B2D/B2B 扩展留口。
- **风险点**：C 端付费转化、创作者变现透明度、内容审核、会员权益与创作者分润的财务一致性、与现有 WorkBuddy 运行时的耦合度。
