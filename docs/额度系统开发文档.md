# New-API 额度系统开发文档

> 本文档整理 new-api 项目的额度（Quota）系统，涵盖核心概念、数据模型、充值流程、消费流程、订阅系统以及管理接口。面向开发者与系统管理员。

---

## 1. 核心概念

### 1.1 额度单位

系统中所有额度以**整数 quota** 为最小单位存储，前端展示时按配置转换为 USD / CNY / Tokens。

- `QuotaPerUnit`：1 USD 对应的 quota 数量（由系统配置决定，通常 `1 USD = 500000 quota`）
- 用户余额、已用额度、模型计费等全部以 quota 计算

### 1.2 额度展示类型

| 展示类型 | 说明 | 转换公式 |
|---------|------|---------|
| `USD` | 美元 | `amount / QuotaPerUnit` |
| `CNY` | 人民币 | `amount / QuotaPerUnit * USDExchangeRate` |
| `TOKENS` | Token 数量 | 直接使用 tokens 数值 |

配置路径：`管理员后台 → 系统设置 → 运营设置 → 额度展示类型`

### 1.3 计费来源

| 来源 | 标识 | 说明 |
|------|------|------|
| 钱包额度 | `wallet` | 用户充值或赠送的额度 |
| 订阅额度 | `subscription` | 用户购买订阅套餐后获得的额度 |

用户可在个人设置中选择计费偏好（`billing_preference`）：
- `subscription_first`：优先使用订阅额度，不足时回退到钱包（默认）
- `wallet_first`：优先使用钱包额度，不足时回退到订阅
- `subscription_only`：仅使用订阅额度
- `wallet_only`：仅使用钱包额度

## 2. 数据模型

### 2.1 用户额度（User）

```go
type User struct {
    Id            int     // 用户ID
    Quota         int     // 剩余额度（quota）
    UsedQuota     int     // 已用额度
    Group         string  // 用户分组（default / video_creator / video_pro / enterprise...）
    AffQuota      int     // 邀请剩余额度
    AffHistoryQuota int   // 邀请历史额度
    // ... 其他字段
}
```

### 2.2 Token 额度（Token）

```go
type Token struct {
    Id            int     // Token ID
    UserId        int     // 所属用户
    RemainQuota   int     // Token 剩余额度
    UsedQuota     int     // Token 已用额度
    UnlimitedQuota bool   // 是否无限额度
    ExpiredTime   int64   // 过期时间
    // ... 其他字段
}
```

- 当 `DisplayTokenStatEnabled = true` 时，OpenAI 兼容接口的 `/v1/dashboard/billing/*` 返回 Token 级别额度
- 否则返回用户级别额度

### 2.3 充值记录（TopUp）

```go
type TopUp struct {
    Id            int     // 记录ID
    UserId        int     // 用户ID
    Amount        int64   // 充值金额（根据展示类型含义不同）
    Money         float64 // 实际支付金额（货币单位）
    TradeNo       string  // 订单号
    PaymentMethod string  // 支付方式（alipay / wxpay / stripe / creem / waffo）
    Status        string  // 状态：pending / success
    CreateTime    int64
    CompleteTime  int64
}
```

### 2.4 订阅套餐（SubscriptionPlan）

```go
type SubscriptionPlan struct {
    Id            int     // 套餐ID
    Title         string  // 标题
    Subtitle      string  // 副标题
    PriceAmount   float64 // 价格（USD）
    Currency      string  // 货币（固定 USD）
    DurationUnit  string  // 周期单位（month / day / custom）
    DurationValue int     // 周期值
    TotalAmount   int     // 套餐总额度（quota）
    QuotaResetPeriod string // 额度重置周期（daily / monthly / custom）
    UpgradeGroup  string  // 升级到的用户分组
    MaxPurchasePerUser int // 每人限购数量（0=不限）
    Enabled       bool    // 是否启用
    // ... Stripe / Creem 关联ID
}
```

### 2.5 用户订阅记录（UserSubscription）

记录用户购买的订阅实例，包含：
- 关联的套餐 ID
- 剩余额度（实时扣减）
- 生效/过期时间
- 状态（active / expired / cancelled）

## 3. 充值流程

### 3.1 支持的支付方式

| 支付方式 | 类型 | 说明 |
|---------|------|------|
| 易支付（Epay） | 第三方支付 | 支持支付宝、微信等，通过易支付网关 |
| Stripe | 国际支付 | 信用卡/借记卡支付 |
| Creem | 国际支付 | 产品化支付 |
| Waffo | 全球支付 | 多币种聚合支付 |

### 3.2 充值流程图

```
用户发起充值
    |
    v
计算实际支付金额（考虑分组倍率 + 折扣）
    |
    v
创建 TopUp 订单（status=pending）
    |
    v
调用支付网关（Stripe / Epay / Waffo / Creem）
    |
    v
用户完成支付
    |
    v
支付网关回调通知（Webhook / Notify URL）
    |
    v
验证签名 → 更新订单 status=success
    |
    v
增加用户 Quota（quota += amount * QuotaPerUnit）
    |
    v
记录日志（LogTypeTopup）
```

### 3.3 充值金额计算

```
// 展示类型为 USD/CNY 时
payMoney = amount * Price * topupGroupRatio * discount

// 展示类型为 TOKENS 时
amount(USD) = tokens / QuotaPerUnit
payMoney = amount(USD) * Price * topupGroupRatio * discount
```

- `Price`：系统配置的单价（USD 每额度单位）
- `topupGroupRatio`：用户分组的充值倍率
- `discount`：充值折扣（可选，按金额阶梯）

### 3.4 关键接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/user/topup` | GET | 获取充值信息（支付方式、金额选项、折扣） |
| `/api/user/topup` | POST | 发起易支付充值 |
| `/api/user/topup/amount` | POST | 计算充值金额（仅计算，不创建订单） |
| `/api/user/epay/notify` | POST/GET | 易支付异步回调 |
| `/api/user/stripe/pay` | POST | Stripe 支付 |
| `/api/user/stripe/webhook` | POST | Stripe Webhook 回调 |
| `/api/user/creem/pay` | POST | Creem 支付 |
| `/api/user/creem/webhook` | POST | Creem Webhook 回调 |
| `/api/user/waffo/pay` | POST | Waffo 支付 |
| `/api/user/waffo/notify` | POST | Waffo 回调 |
| `/api/user/topup/history` | GET | 用户充值记录 |
| `/api/admin/topups` | GET | 管理员查看全平台充值记录 |
| `/api/admin/topups/complete` | POST | 管理员手动补单 |

## 4. 消费流程

### 4.1 预扣费 + 结算机制

系统采用**预扣费 + 后结算**模式，防止用户超额消费：

```
请求到达
    |
    v
创建 BillingSession
    |
    v
预扣费（PreConsume）
  ├── 信任额度旁路：用户额度充足时跳过预扣
  ├── 预扣 Token 额度
  └── 预扣资金来源（钱包/订阅）
    |
    v
请求上游服务
    |
    v
结算（Settle）
  ├── 计算实际消耗额度
  ├── 补扣或返还差额
  └── 更新 Token 额度和用户额度
    |
    v
请求失败时退款（Refund）
  ├── 异步退还资金来源
  └── 异步退还 Token 额度
```

### 4.2 信任额度旁路

当用户满足以下条件时，系统**信任**其额度充足，跳过预扣费：
- 用户剩余额度 > `TrustQuota`（系统配置）
- Token 剩余额度 > `TrustQuota` 或 Token 为无限额度
- 计费来源为钱包（订阅不启用信任旁路）
- 非异步任务（`ForcePreConsume = false`）

### 4.3 BillingSession 核心逻辑

```go
type BillingSession struct {
    relayInfo        *RelayInfo   // 请求上下文
    funding          FundingSource // 资金来源（钱包/订阅）
    preConsumedQuota int          // 实际预扣额度
    tokenConsumed    int          // Token 预扣量
    fundingSettled   bool         // 资金是否已结算
    settled          bool         // 是否已完全结算
    refunded         bool         // 是否已退款
}
```

关键方法：
- `PreConsume(c, quota)`：预扣费，失败时原子回滚
- `Settle(actualQuota)`：按实际消耗结算差额
- `Refund(c)`：退款（幂等安全，异步执行）

### 4.4 订阅计费

订阅计费特点：
- 每次请求至少预扣 1 quota（即使 `preConsumedQuota <= 0`）
- 订阅额度在 `user_subscriptions` 表中实时扣减
- 不支持信任额度旁路（必须锁定订阅记录）

### 4.5 模型计费

模型计费取决于 `model_price` 和 `model_ratio`：

| 计费方式 | 条件 | 公式 |
|---------|------|------|
| 按 token 计费 | `model_price == 0` | `quota = prompt_tokens * model_ratio + completion_tokens * model_ratio * completion_ratio` |
| 按次计费 | `model_price > 0` | `quota = model_price * QuotaPerUnit` |

### 4.6 额度通知

当用户额度低于阈值时，系统发送通知：
- 订阅额度不足通知
- 钱包额度不足通知

## 5. 订阅系统

### 5.1 订阅套餐管理

管理员可在后台创建/编辑订阅套餐：

| 配置项 | 说明 |
|--------|------|
| 标题/副标题 | 套餐展示名称 |
| 价格 | USD 金额 |
| 周期 | 月/日/自定义 |
| 总额度 | 套餐包含的 quota |
| 额度重置周期 | 每日/每月/自定义 |
| 升级分组 | 购买后用户自动升级到的分组 |
| 限购 | 每人最多购买次数 |

### 5.2 用户订阅流程

```
用户浏览订阅套餐
    |
    v
选择套餐 → 支付（Stripe / Creem）
    |
    v
创建 UserSubscription 记录
    |
    v
用户分组自动升级（如配置 UpgradeGroup）
    |
    v
额度按重置周期自动重置
    |
    v
订阅到期后自动降级回 default 分组
```

### 5.3 关键接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/user/subscription/plans` | GET | 获取可用订阅套餐 |
| `/api/user/subscription/self` | GET | 获取当前用户订阅状态 |
| `/api/user/subscription/preference` | PUT | 修改计费偏好 |
| `/api/admin/subscription/plans` | GET/POST | 管理员管理套餐 |
| `/api/admin/subscription/plans/:id` | PUT/DELETE | 更新/删除套餐 |
| `/api/admin/subscription/users/:id` | GET/POST/DELETE | 管理用户订阅 |

## 8. 配置速查

### 8.1 关键系统配置

| 配置项 | 路径 | 说明 |
|--------|------|------|
| 额度展示类型 | 运营设置 | USD / CNY / TOKENS |
| 单价（Price） | 运营设置 | 每额度单位的 USD 价格 |
| 信任额度（TrustQuota） | 运营设置 | 触发信任旁路的额度阈值 |
| 最低充值金额 | 支付设置 | MinTopUp |
| 充值金额选项 | 支付设置 | AmountOptions |
| 充值折扣 | 支付设置 | AmountDiscount |
| 分组倍率 | 分组与模型倍率 | group_ratio |

### 8.2 分组定价示例

```
实际价格 = 模型定价 × 分组倍率

default 组：倍率 1.0（视频模型可能额外 × 2.0）
video_creator 组：倍率 1.0
video_pro 组：倍率 0.8
enterprise 组：倍率 0.6
```

## 9. 注意事项

1. **并发安全**：充值回调使用订单级互斥锁（`refCountedMutex`），防止重复充值
2. **幂等性**：所有支付回调均做幂等处理，重复回调不会重复加额度
3. **事务一致性**：充值和扣费操作均使用数据库事务，确保额度变更与订单状态一致
4. **分组降级**：订阅到期后自动降级回 `default` 分组，价格恢复默认倍率
5. **免费套餐**：可配置 `PriceAmount = 0` 的免费套餐，每人限购 1 次
6. **跨数据库兼容**：所有额度相关 SQL 兼容 SQLite / MySQL / PostgreSQL
