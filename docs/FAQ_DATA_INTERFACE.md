# FAQ 数据接口文档

> 本文档供后端开发和下游前端团队参考，用于在提示词和文章数据中补充 FAQ 字段，以支持前端 GEO 优化（FAQPage Schema 注入）。

## 一、数据存储格式

FAQ 在数据库中以 **JSON 字符串**形式存储，结构如下：

```json
[
  {"question":"...","answer":"..."},
  {"question":"...","answer":"..."}
]
```

字段说明：

| 字段      | 类型   | 必填 | 说明                                   |
|-----------|--------|------|----------------------------------------|
| `faq`     | string | 否   | JSON 字符串，支持 `array` 或 JSON string |
| `question`| string | 是   | FAQ 问题，建议用自然语言搜索式           |
| `answer`  | string | 是   | 首句直接给结论，建议 100–300 词          |

---

## 二、提示词详情页 FAQ（Prompt Detail）

### 2.1 数据来源

| 语言 | 数据来源 | 回退机制 |
|------|---------|---------|
| 中文 (`zh` / `zh-CN`) | 根字段 `faq` | — |
| 其他语言 | `seo_i18n[lang]?.faq` | 缺失时回退到根字段 `faq` |

`seo_i18n` 为 JSON 字符串，结构如下：

```json
{
  "ja": {
    "seo_keywords": "...",
    "intro": "...",
    "faq": [
      {"question":"...","answer":"..."}
    ]
  },
  "en": {
    "seo_keywords": "...",
    "intro": "...",
    "faq": [
      {"question":"...","answer":"..."}
    ]
  }
}
```

### 2.2 前端触发条件

- 当 `faq.length >= 3` 时，前端自动注入 **FAQPage JSON-LD Schema**，并在页面底部显示 FAQ Accordion 折叠列表。
- 当 `faq.length < 3` 时，**不注入 Schema，也不显示 FAQ 区块**。

### 2.3 FAQ 数量建议

| 指标 | 建议值 |
|------|--------|
| 最低 | 3 题（触发 Schema 的门槛） |
| 推荐 | 5–8 题（GEO 效果最佳区间） |
| 上限 | 单页不超过 10 题（避免页面过长） |

## 三、文章详情页 FAQ（Article Detail）

### 3.1 数据来源

文章 FAQ 的数据来源与提示词完全一致：

| 语言 | 数据来源 | 回退机制 |
|------|---------|---------|
| 中文 (`zh` / `zh-CN`) | 根字段 `faq` | — |
| 其他语言 | `seo_i18n[lang]?.faq` | 缺失时回退到根字段 `faq` |

> ⚠️ **注意**：文章 FAQ 从 `seo_i18n` 读取多语言，不是从 `i18n`。`i18n` 字段仅用于存储文章内容的多语言翻译。

### 3.2 前端触发条件

与提示词相同：`faq.length >= 3` 时注入 Schema + 显示 FAQ 区块；否则不注入、不显示。

## 四、Public API 多语言支持

### 4.1 列表接口

```
GET /api/public/prompts?lang=ja&page=1&size=20
GET /api/public/articles?lang=ja&page=1&size=20
```

当传入 `lang` 参数时，接口会自动替换返回数据的 `title` 和 `content`：
- `lang=ja` → 返回日文 `title` + `content`
- `lang=en` → 优先返回 `content_en`，没有则从 `i18n` 中取
- 不传或传 `zh` → 保持中文不变
- 对应语言没有翻译数据 → 保持中文不变（兜底）

> **注意**：FAQ 数据不会通过 `lang` 参数自动替换，前端需自行根据 `seo_i18n` 和 `faq` 字段解析。

### 4.2 详情接口

```
GET /api/public/prompts/{slug}?lang=ja
GET /api/public/prompts/{id}?lang=ja
GET /api/public/articles/{slug}?lang=ja
GET /api/public/articles/{id}?lang=ja
```

同样支持 `lang` 参数自动切换 `title` 和 `content`。

## 五、优先填充建议

### 5.1 提示词 FAQ（高优先级）

建议为流量 Top 20 的提示词补充 FAQ，每套至少 3 题：

- 这个提示词适合生成什么风格的内容？
- 使用该提示词需要注意哪些参数设置？
- 生成结果不理想时如何调整？
- 该提示词支持哪些 AI 模型？
- 生成的内容可以商用吗？

### 5.2 文章 FAQ（中优先级）

为教程类文章补充 FAQ，每篇 3–5 题：

- 本文教程适合什么水平的用户？
- 按照教程操作需要准备什么前置条件？
- 教程中的功能需要付费吗？
- 操作过程中常见问题如何解决？

## 六、GEO 写作规范

为最大化 AI 搜索引擎引用率，FAQ 内容请遵循以下规范：

1. **首句结论**：答案第一句直接给出明确结论（Yes/No/数字/定义）。
2. **自然语言问题**：尽量用用户真实搜索语句，如 "HarseTV 支持离线使用吗？" 而非 "离线功能"。
3. **答案长度**：100–300 词，太短 AI 不引用，太长用户不看完。
4. **结构化**：用分点、数字列表、加粗关键词提升可读性。
5. **关键词自然嵌入**：在答案中自然出现产品名、功能名、模型名。

## 七、验证方法

### 7.1 页面级验证

1. 访问提示词/文章详情页，确认页面底部出现 FAQ 折叠列表。
2. 切换语言（如日语、英语），确认 FAQ 问题与答案已切换为对应语言。

### 7.2 Schema 验证

1. **F12 DevTools → Elements 面板**，搜索 `FAQPage`，确认存在且仅有一个 JSON-LD `<script>`。
2. **Google Rich Results Test** 测试 URL，确认检测到 `FAQPage` + `Article` 结构化数据。

> ⚠️ **不要**使用「右键 → 查看网页源代码」搜索，本项目为 SPA（单页应用），SEO 标签由 JS 动态注入，源代码中不可见。

## 八、自动生成 FAQ（管理后台功能）

管理后台支持对提示词和文章「自动生成 FAQ」：

- **入口**：提示词管理 / 文章管理 → 勾选项目 → 点击「自动生成 FAQ」
- **机制**：调用 AI 根据标题和内容自动生成 3–5 条 FAQ，保存到 `faq` 字段（中文）
- **多语言**：生成后可执行「批量 SEO 翻译」，将 FAQ 自动翻译到 `seo_i18n` 各语言
- **建议**：生成后人工审核，AI 内容不一定 100% 准确
