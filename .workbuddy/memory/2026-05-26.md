- 2026-05-26: 修复支付回调地址出现 `<nil>` 导致易支付跳转失败的问题。根因：数据库中 `ServerAddress` 或 `CustomCallbackAddress` 存储了字符串 `"<nil>"`。修复：`service/epay.go` 增加 `isInvalidAddress()` 过滤空字符串和 `"<nil>"`；`controller/topup.go` 中 `ServerAddress` 无效时从请求 Host 自动推断兜底地址。已 push stable（commit `5642482f`）。
- 2026-05-26: 修复任务轮询时未检查上游 HTTP 状态码导致任务状态不更新的问题。`updateVideoSingleTask` 中 `FetchTask` 后未检查 `resp.StatusCode`，当上游返回 404（任务不存在）或 HTML 错误页时，`ParseTaskResult` 解析失败返回 error，外层仅 LogError 不更新任务状态，应用端永远看不到失败。修复：4xx 直接标记任务为 FAILURE 并解析错误消息；5xx 返回 error 等待下一轮轮询。修复了 `else if` 短变量声明语法错误，以及 `controller/topup.go` 中未使用的 `system_setting` 导入。已 push stable（commit `075fb390`）。
- 2026-05-26: 修复轮询饥饿导致新任务状态不更新的问题。根因：`GetAllUnFinishSyncTasks` 按 `id ASC` 排序且 `limit=1000`，当未完成任务超过 1000 时新任务（ID 大）永远进不了轮询队列。修复：`model/task.go` 改 `Order("id DESC")` 让新任务优先；`common/init.go` 把 `TASK_QUERY_LIMIT` 默认值从 1000 提高到 5000。已 push stable（commit `30951bab`）。
- 2026-05-26: 修复 apimart 渠道不支持下游 `image_urls` 参考图字段的问题。根因：`TaskSubmitReq` 只定义了 `images` / `image` JSON 标签，下游按 OpenAI 标准发 `image_urls` 时解析不到，参考图丢失。修复：`relay/common/relay_info.go` 增加 `ImageURLs` 字段；`relay/channel/task/apimart/adaptor.go` 收集参考图时优先 `images`，其次 `image_urls`，最后兜底 `image`；`HasImage()` 同步检查三个字段。已 push stable（commit `48c90a7d`）。
- 2026-05-26: 修复 Docker build 因服务器内存不足被 OOM Killer 杀掉的问題。根因：Dockerfile 中 node builder 阶段执行 `vite build` 需要 4GB+ 内存，服务器内存不够。修复：删除 Dockerfile 中的 node builder 阶段，改为依赖宿主机预先 build 好的 `web/dist` 目录。已 push stable（commit `7cea9e73`）。

- 2026-05-26: 修复 zhangyuge 渠道 `submitResponse.error` 字段解析失败的问题。根因：上游返回 `error` 为对象（`{"message":"..."}`），但代码定义成 `string` 类型，导致 `ParseTaskResult` 时 `unmarshal` 失败，任务状态无法更新。修复：`relay/channel/task/zhangyuge/adaptor.go` 将 `Error` 字段改为 `any` 类型，并在 `ParseTaskResult` 中兼容处理 string/object 两种情况。已 push stable（commit `b947d817`）。
- 2026-05-26: 修复 veo 渠道 `history not found` 导致无限轮询报错的问题。根因：veo 的 `FetchTask` 在找不到历史记录时直接返回 error，通用轮询逻辑只打日志不更新任务状态，旧任务永远卡在 IN_PROGRESS 并不断报错。修复：`relay/channel/task/veo/adaptor.go` 中找不到历史记录时返回 404 HTTP response，让通用轮询逻辑按 4xx 规则标记任务失败。已 push stable（commit `b947d817`）。
